# Decisions on record

Choices already made, with the reasons. Check here before reopening one; ideas still to discuss are in [backlog.md](backlog.md).

- **Substack: not supported.** It has no official posting API. An unofficial route exists (session cookie + internal `/api/v1/comment/feed` for Notes), but it may break without notice and may violate their terms. On 2026-11-09 it was built for Notes on the `feature/substack-notes` branch and tested live: the cookie and image upload worked, but Cloudflare blocks publishing (`/comment/feed` returns a 403 page) unless the request carries the browser's `cf_clearance` bot-check cookie. Reusing that cookie or imitating a browser would be circumventing the bot check, so it won't be done. The branch is kept in case Substack opens an official API. Instead, every post ends with a reminder to post it on Substack by hand (Copy text, Share for photos, the saved video's path on the web page). Handing Notes to Substack's app with text and photos filled in was dropped on 2026-11-17: it needs a package that doesn't run in Expo Go.
- **Reddit: not supported (2026-11-17).** Reddit stopped taking public Data API requests on 2026-10-31 and declined this app's request on 2026-11-17, pointing to its Developer Platform (Devvit). Devvit apps are installed per subreddit and can post as a user only from a click inside Reddit (scheduled jobs can post only as the app's account), so they can't post from Socialifer. If API access ever opens, Reddit posts only to the signed-in user's own profile, never to a subreddit (destination fixed in code); scopes `identity` and `submit` only; no scheduled posting, voting, comments, messages or reading other content. The README promises this publicly, so don't loosen it. The empty `feature/reddit-idea` branch is kept.
- **Instagram and Threads media need `TUNNEL_URL`**, because Meta fetches media from a URL. Instagram's resumable upload (direct video upload) is only available to Facebook Login for Business apps, and images still need a URL, so the tunnel approach was chosen for both.
- **"Finish by hand" after posting (2026-11-17):** one dialog for what's left to do by hand: the Substack reminder, and platforms' own items (a `todo: { text, label, url }` returned by `post()` and carried in its result). YouTube adds one when the uploaded video is private and not scheduled, linking to it in YouTube Studio. Visibility starts at Private for every post (not remembered), so publishing is a deliberate step there.
- **Substack reminder on the web page:** part of "Finish by hand", a dialog that closes only with Done. Text and image posts get it right after Post; video posts once every platform has finished, with a copy of the video saved to `~/Videos/Socialifer` (X's copy, else Instagram's, else another burn-in platform's, else the original; `keptVideos` in `publish.js`). Done deletes them (`POST /api/kept/delete`, which only touches files directly in that folder).
- **Alt text on X and Instagram only.** Bluesky, Mastodon and LinkedIn also support it; adding it there is a possible follow-up.
- **Thumbnails are never shrunk for the user.** They make the smaller copy themselves and so see how it looks; an automatic shrink could spoil it and the app would get the blame. (Phone photos being too big is an open question in the backlog.)
- **YouTube Posts (Community) aren't supported:** checked 2026-11-17, the YouTube Data API has no resource or method for them (`commentThreads` only makes comments), and Google hasn't announced one.
- **ffmpeg is optional**, not a dependency. It is found on PATH, in `FFMPEG_DIR`, or in winget's Links folder (`%LOCALAPPDATA%\Microsoft\WinGet\Links`), because VS Code terminals opened before an install don't see the new PATH. Without it, oversized videos are rejected per platform as before.
- **Videos are compressed, never trimmed.** A video that is too long for a platform is a problem the user must fix; only size is adjusted automatically. Compression targets the platform's `videoMB` with H.264/AAC, scaling so the shorter side is at most 1080 px (`SCALE` in `media.js`), and refusing to go below 400 kbps video (`compressionBitrate` in `public/rules.js`).
- **YouTube uploads start private** until the user's Google Cloud project passes YouTube's API audit. This can't be worked around in code; the UI and README say so. Shorts are not a separate upload type.
- **Subtitles: a track per language on YouTube, one language burned in elsewhere.** Generating them belongs to the separate transcribe project; this app only runs it (see [subtitles.md](subtitles.md)). Waiting for YouTube's automatic captions before posting to the others was rejected, because posts must not wait. Overlapping lines (as in YouTube's auto captions) are trimmed with `separateCues` in `public/rules.js` everywhere, never in the user's file. Generated SRTs never overlap (transcribe promises it), but `separateCues` still runs on every SRT: it's needed for uploaded ones, and it's the last check before a platform. On a Windows PC, burned-in text uses Nirmala UI because Arial has no Devanagari.
- **Brand: Socialifer (2026-11-17).** New name, Ring of fire logo, Dusk Plum colour, Inter and Noto Sans Devanagari, and the voice (friendly on success, calm otherwise). How the logo was chosen, with the options explored: the "Socialifer logo" artifact, https://claude.ai/artifact/QCqti7p3vUfmGdzSjmGL6L (private to the user). In the web app and the app since 2026-11-17 (name, mark, colours, fonts); and in the README, docs, package name and the `~/Videos/Socialifer` folder. The rest of the rollout is in section 9 of [backlog.md](backlog.md). Saved settings keep their `social-post:` keys, so nothing has to be carried over. The app's fonts use `expo-font` (approved 2026-11-17); Hindi falls back to Android's own Noto Sans Devanagari.
- **Scheduling (2026-11-18):** posts go out 9 AM to 11 PM; image and video posts 4 hours apart with 2 of each a day; text posts 1 hour apart (a burst on one account looks like spam); a text post and an image or video post 1 hour apart only when they share a platform. No other per-platform slots, because the user hasn't researched per-platform timing and doesn't want to. Missed posts move to the next free time. Posts are kept as files in `POSTS_DIR` outside the project, not in a database. Details in [scheduling.md](scheduling.md).
- **App fixes from phone testing (2026-11-19):**
  - **UI library:** React Native Paper (stable v5), over gluestack-ui, React Native Reusables and Tamagui; Android look, and the parts the bugs needed (FAB, snackbar, radios, chips, dialogs, bottom tabs). Themed in `mobile/src/ui.js` (plum, Inter). It brought `react-native-safe-area-context` and `@expo/vector-icons` (approved).
  - **Pairing on demand:** the app opens on Posts without pairing, and posts are saved as usual; a red note on Posts says it isn't paired, with Pair now (also on the Laptop screen). Nothing forces pairing. 
  - **Only set-up platforms are offered:** "Post to" (app and web page) shows only platforms with credentials in the laptop's `.env`; the web page's "Set up more" list is gone, since six platforms were never tried live and it made them look ready. Before the first pairing the app says "Pair once to choose platforms" (the list comes from the laptop; a shared platform file was considered and dropped). A post that already has an unset platform keeps it, flagged, and can't be posted until it's fixed.
  - **APK for 64-bit ARM only** (`plugins/arm64-only.js`): the universal APK was about 90 MB; old 32-bit phones and Intel emulators can't install it.
  - **Cancel and Delete:** Cancel keeps a post as history, marked cancelled, on the laptop and the phone; Delete removes it everywhere (the laptop keeps only its id, so the phone can follow). On the web page and the app, for any post. Socialifer never deletes a video from YouTube: it links to YouTube Studio.
  - **Immediately:** a third When choice that ignores posting hours and gaps ("sometimes we just want to send a post").
  - **Simple Calendar:** Scheduled · Posted · Cancelled only; the rest is in the post's details, and an ⓘ replaces the legend.
  - **App tabs:** Posts · Calendar; the ＋ button starts a post, which is full screen. The web page keeps Write as its first view.
  - **Message colours:** red for errors (something to fix), orange for warnings (can go on), grey for a plain next step.
  - **Logs (2026-11-20):** ISO 8601 times with the zone offset, so logs from users in other countries read correctly; one timing line per post to check the scheduling.
  - **Posting hours are a block, not a warning:** a picked time outside 9 AM to 11 PM is refused by the page, the app and the laptop (`outsideHours` in `public/rules.js`).
  - **Substack from a text post:** Share text opens Android's share sheet (pick Substack's app), next to Copy text.
- **X limit defaults to 280**; `X_CHAR_LIMIT` exists for Premium accounts (up to 25,000).
